# WTS 人类可读 Case 双文档设计

## 目标

将 Domi 会话数据库中的完整事件流转换为适合人阅读和比较的 WTS 测试 Case。Case 同时服务两个目标：

1. 检查 Agent 的可观察执行过程是否遵循 WTS 要求。
2. 发现规范之外但有价值的判断、策略和自我修正。

这里的“思考过程”仅指可观察决策：Agent 对用户说了什么、调用了什么工具、产生了哪些中间结果、如何根据结果选择下一步；不包含模型内部隐藏推理。

## 文件结构

每个 Case 在对应版本的 `conversations/` 目录中使用两个 Markdown 文件：

```text
case-001.md
case-001-review.md
```

- `case-001.md` 是对原始事件流的忠实、可读投影。
- `case-001-review.md` 是基于可观察证据的复盘点评。
- 脱敏后的 `messages.json` 保留在导出目录中作为机器可读追溯源，不直接作为日常阅读入口。

## 可读原稿映射

`case-001.md` 按以下顺序组织：

1. **会话信息**：Skill 版本、Case 编号、Session ID、测试时间、任务状态。
2. **用户原始需求**：逐字保留用户消息。
3. **执行过程**：按 WTS 阶段分组，而不按数据库事件类型堆叠。
4. **Agent 最终答复**：逐字保留最终面向用户的文本。
5. **原始数据索引**：标明对应的脱敏 `messages.json` 和 Session ID。

执行过程保留：

- Agent 对用户可见的阶段性文本。
- 交互问题、全部选项与用户实际选择。
- 需求确认、目标公司、SearchPlan、硬筛、评分、反思、Controller 和停止决策等关键中间结果。
- 实际搜索词、筛选条件、每轮召回/新增/推荐数量。
- 错误、失败、重试、策略改变及其直接依据。

执行过程不保留：

- `model_activity` 心跳、隐藏推理和无新信息的进度通知。
- 重复的 request ID、trace ID、父子请求链和时间字段。
- 已在上文展示过的完整候选人 JSON、Skill 全文和工具协议字段。
- 对决策复盘没有影响的成功状态重复。

工具事件转换为统一的人类可读记录：

```markdown
### 第 1 轮检索

**Agent 决策**
主路径使用“系统架构师 + X86 + 华为”，第二路径放宽为“系统架构师 + AI 服务器”。

**执行与结果**
- 主路径：首屏 30 人，详情 5 人。
- 第二路径：首屏 30 人，详情 3 人。

**下一步依据**
强匹配不足，Agent 保留 X86 硬件边界，改用高分候选人的历史公司扩充公司词。
```

编辑性文字只负责串联事件，不得补写原始记录中没有的理由。推断必须标记为“复盘推断”并放入 Review，不混入原稿。

## 复盘点评映射

`case-001-review.md` 包含：

1. **一句话结论**：整体执行质量和最重要的观察。
2. **SOP 遵循情况**：按要求标记“遵循 / 部分遵循 / 未遵循 / 无法观测”，并链接到原稿证据。
3. **关键决策链**：需求理解、公司调研、查询设计、结果评价、轮次调整和停止条件。
4. **智能涌现**：记录规范没有明确要求、但 Agent 表现出的有价值判断。
5. **问题与风险**：遗漏、机械执行、无证据推断、重复和错误处理不足。
6. **版本启发**：区分“值得写回 Skill 的能力”和“本次偶然表现”。
7. **评价边界**：说明点评基于可观察证据，不声称读取内部思维。

“SOP 遵循”与“智能涌现”必须分开。每个涌现项至少包含：

- 观察到的行为。
- 为什么它有价值。
- 对应的原稿证据。
- 是否建议固化到后续 Skill。

## 数据流

```text
SQLite 原始记录
    ↓ 只读查询、extra_metadata 解析、凭证脱敏
messages.json
    ↓ 事件归类、去重、按 WTS 阶段重组
case-001.md
    ↓ 与冻结版 Skill 要求对照
case-001-review.md
```

Review 不能成为 Transcript 的数据源。所有点评都必须能回指到 `case-001.md` 中的可观察证据，必要时再通过 Session ID 追溯 `messages.json`。

## 异常与保真

- 缺少阶段事件时标记“未观测到”，不猜测它是否执行。
- 工具结果被截断时标记“源记录已截断”，不将部分数据写成完整结论。
- 用户和 Agent 原文只做凭证脱敏，不改写或摘要。
- 候选人姓名、联系方式和可直接定位个人的链接继续按现有隐私规则脱敏。
- 生成后校验 Session ID 唯一性、消息完整性、最终答复一致性和凭证扫描结果。

## 验收标准

- 读者先看 Review，5 分钟内能说出本次是否遵循 SOP、主要问题和最有价值的智能涌现。
- 读者可通过 Transcript 检查点评证据，无需阅读重复 JSON 和底层事件噪声。
- 用户原始需求和 Agent 最终答复与脱敏后源数据一致。
- 关键决策、用户选择、检索词、每轮结果、错误和调整均可在 Transcript 中找到。
- Review 中每个关键判断都有 Transcript 证据，不将推测写成事实。
