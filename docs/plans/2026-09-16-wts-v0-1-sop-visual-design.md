# WTS 0.1 SOP 可视化网页设计

## 目标

为产品经理和业务团队制作一份 5–10 分钟可看懂的 WTS 0.1 SOP 可视化网页。内容应帮助读者理解整体流程、关键判断、用户参与点和最终产物，不展开底层 JSON 字段、选择器或代码实现。

## 内容来源

仅使用 `versions/wts-v0-1/` 中的已冻结文件：

- `SKILL.md`
- `references/requirements-draft.md`
- `references/target-company-research.md`
- `references/search-plan.md`
- `references/scoring.md`
- `references/prf.md`
- `references/final-report.md`

不将推测内容写成已实现功能。

## 信息架构

1. **首屏**：一句话说明 WTS 0.1，并展示 `JD → 澄清 → 确认 → 检索 → 评分 → 报告`。
2. **核心原则**：两阶段、一条确认门、唯一主池、最多三轮检索、逐轮决策。
3. **主流程图**：串起从 JD 输入到终态报告的全链路。
4. **六个关键节点**：需求拆解、五类澄清、目标公司、需求确认门、多轮检索、Top 10 终态报告。
5. **检索循环**：`SearchPlan → 搜索 → 硬筛 → 详情 → 评分 → 反思 → Controller`。
6. **结束条件**：强池形成、轮次用完、无新候选人、需要人工处理或致命错误。
7. **输出物**：候选人画像、搜索计划、Top 10 榜单、市场洞察、备选方向。

## 视觉与交互

- 使用简洁的产品架构图风格，避免流程图过密。
- 用颜色区分四类节点：用户参与、Agent 判断、浏览器执行、异常暂停。
- 默认保持一屏可掌握整体逻辑；关键节点支持点击或键盘展开简短说明。
- 同时支持桌面和移动端；不依赖外部 CDN，便于本地展示和转发。
- 提供清晰的图例和当前流程层级，不使用隐晦的内部术语作为主标题。

## 验收标准

- 产品经理能在 5–10 分钟内说出 WTS 0.1 的全链路。
- 主流程与冻结版 Skill 一致，不遗漏用户确认门、多轮检索、评分和停止决策。
- 用户操作与 Agent/浏览器自动执行的边界一眼可辨。
- 网页可在本地直接打开，关键交互可用键盘操作，常见桌面和移动端宽度下无水平溢出。
