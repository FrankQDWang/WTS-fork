# WTS 0.2：分散等待验证

日期：2026-09-16。**Skill 实现完成；BLOCKED_RUNTIME，未安装或访问猎聘。**

## 行为与耗时

- 将集中在详情打开前的 15 秒，分配到读取列表位置、点击打开、提取详情三个操作前；每段约 4–6 秒，每份合计恰好 15 秒。不同候选人独立生成分配，跨路径和轮次都覆盖。
- 普通点击、输入、按键和内容读取，以原 action_delay_ms（默认 1200 ms）为基准浮动 ±20%。点击的原固定尾延迟被替换，而非叠加。一次批量读取为一个操作，不在 DOM 字段、条件轮询或浏览器内部事件之间等待。
- 页面导航后先即时安全检测，再浮动等待。验证码检测、加载轮询、取消响应和纯数据处理不增加等待。
- 随机值在编译时固化为已支持的 page.wait，按 foreach 的候选人索引选择，无运行时随机 API 依赖。同一工作流重放保留原值，新编译重新抽样。
- 常规详情等待与最初的固定等待方案相同；普通操作额外覆盖会带来小幅开销。示例：三个无额外筛选的主路径、每路五份详情，固定等待方案新增 225 秒，本版相对原始 0.1 新增约 **232.92–238.68 秒**（增加约 3.5%–6.1%）。此估算不包含前置检查、公司探测、条件性列表恢复及页面加载耗时；没有详情的查询也会对普通操作节流。
- 搜索、筛选、评分、候选人预算和轮次保持不变。捕获超时根据生成的前置等待上界加原页面恢复/点击预算计算，拒绝超过宿主 120 秒上限的配置。

## 验证

```sh
python3 -B -m unittest discover -s tests -v
node tests/check_domi_runtime.cjs /Applications/Domi.app
```

7 项 Python 测试通过，覆盖源和 0.2：所有轮次、主次路径、前置检查、探测、零详情、筛选分支、普通操作覆盖、候选人索引、每份 15 秒预算、±20% 边界、15 份总体预算、包身份及原业务逻辑等价。固定等待草案已由本版取代。

本机 Domi 1.0.40 的原始工作流校验器接受生成结果。原 tabs.foreach 调度、捕获、等待、条件索引选择及验证码识别函数在本地模拟页面传输边界运行，未启动 Electron 或外网访问，不等于完整浏览器端到端测试。

本次三份模拟详情共九段等待，计划合计 45 秒。示例第一份分配为 5.327 / 5.086 / 4.587 秒，第二份为 5.216 / 4.882 / 4.902 秒。每段实测不短于计划。等待取消约 205 ms 完成，无点击；验证码识别和仍存在时暂停检查通过。原始时间线和运行器文件哈希见 [wts-v0-2-runtime-results.json](wts-v0-2-runtime-results.json)。
