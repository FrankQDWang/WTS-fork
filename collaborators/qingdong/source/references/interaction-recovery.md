# 交互恢复

参数报错、卡片未出现或恢复中断时读取。确认仍通过 `request_user_input` 卡片完成。

- **明确未执行的参数错误**：按真实报错修正字段或 JSON 闭合，保留问题和全部选项，独占重发一次。仍失败时说明“确认卡片未能发出，当前停在……”，保留待确认状态；只有用户明确选择文字确认，才改用文字收集答案。
- **已等待或状态不明**：从当前对话的工具记录核对有无待答卡片及答案。已有卡片则等待；执行状态不明就说明尚不能确认，避免重复提交。用户取消或停止时保持停止。
- **用户询问原因**：只回答问题，以可见工具记录为依据。通用的 malformed/truncated 报错不足以区分括号错误、额外包装或长度截断；没有原始参数就标明原因未证实，不把猜测写成事实，也不重发表单。
- **用户明确要求继续或重发**：从未完成的确认点继续，复用现有调研和已答内容；拿到答案后才更新确认结果。调研正文输出、参数生成或对话结束都不算用户确认。

脚本对文件的校验不能保证模型最终发出的工具参数合法。宿主若在解析失败后直接结束推理，这些规则只能在下一次获准执行时生效。
